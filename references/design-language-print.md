## 1. 定位：这不是现有路书的「换肤」，是另一套语言

现有 `design-language.md` 的五条核心纪律，本语言**四条正面冲突**：

| 现有纪律（瑞士/包豪斯） | 本语言 | 冲突 |
|---|---|---|
| 单一强调色 = 朱红 `#e0362b` | 强调橙 `#d9561e` **+** 砖红 `#96442e` **+** 灰橄榄 `#bcb99a` | ⚠️ 是 |
| 发丝线 1px 分隔 | 副标题下分隔线 **5px**；数据条边框 2px | ⚠️ 是 |
| 全 sans 字体栈（`Inter`/`PingFang SC`） | **全衬线**（中文宋 + 西文 serif） | ⚠️ 是 |
| 扁平、无大圆角（`rx="1"`） | 胶囊标签是大圆角（接近半高） | ⚠️ 是 |
| 左对齐字阶 | **居中对称**排版 | ⚠️ 是 |

**结论**：它和「功能版渲染器」是同一类东西——不是路书的一种皮肤，而是**另一种产物**。
当年「功能版」因与包豪斯身份冲突而退役（见 `SKILL.md` §5 注）。接入本语言前请先读 §8。

**它真正对应的产物形态**：一页**分享海报**（封面 / 小红书 / 朋友圈），
与「多段信息页的路书」互补，而不是替代。

## 2. 设计哲学：复古印刷 / 旅行海报

- **纸不是白的**：整张是暖米黄纸底，带印刷品的时间感。留白极多，信息密度远低于路书。
- **一条线讲完路线**：地图是画面的主体（约占 1/2 高），不是配图。路线本身承担叙事。
- **数字是主角**：`80` / `134` / `72` 用超大字重衬线，比汉字标题还大 39%。汉字让位给数字。
- **核验做成印章**：`已骑行 ✓ 亲测 2026.10.1` 是一枚倾斜的砖红印章，压在图上——
  把「这趟是真的走过」变成视觉元素。**这条与本 skill 的 `verify[]` 语义完全对应**（见 §8 决策 3）。
- **双线外框**：外线 + 内线，模拟老印刷品的版框。

## 3. 设计令牌（实测）

```
--paper:   #f4eede   暖米黄纸底（占全图 66.3%）
--ink:     #392b1e   暖深棕墨（H=20° S=0.49 V=0.22）—— 不是纯黑，这是暖调的关键
--accent:  #d9561e   强调橙（主标题数字、路线、数据条中格）
--brick:   #96442e   砖红（分隔线、印章、胶囊描边与字、POI 图标）
--olive:   #bcb99a   灰橄榄（双线外框、数据条竖分隔线、山形符号）
--olive-2: #d4cfbc   更浅的灰橄榄（内框线）

--pill-bg: #ede7cf   胶囊底色（比纸底略深）
```

**⚠️ 本语言没有绿色。** 图上的「树」经两种方法复核（色相聚类 + 切图目视）确认是
**三座小房子**（村落/小镇符号），用了 `#d9561e` / `#96442e` / `#bdb5a2` 三个色。
不要凭「小绿汁」这个地名去补一个绿色——原图没有。

字体栈（按可见特征选开源替代，非原图字体）：

```
"Source Han Serif SC","Noto Serif SC","Songti SC",serif          /* 中文：宋/明朝体 */
"Source Serif 4","EB Garamond","Georgia",serif                   /* 西文正文与小字 */
"Playfair Display","Source Serif 4",serif                        /* 大号数字/标题 */
```

原图字体未核实（只写可见特征）：中文为**宋体**；西文与数字为**衬线**，大号数字字重很重、
笔画对比强；`MOTO ROUTE` / `KUNMING → LVZHI` 为**加大字距的小号大写**。

## 5. 组件清单（10 个）

1. **双线外框** —— 外 2px + 间隙 8px + 内 1px，灰橄榄色，绕全图一周。
2. **报头** —— 左「字距小标 · 出发地」／右「起讫点 →」，同基线，灰橄榄或砖红小字。
3. **主标题** —— 汉字墨色 + 数字橙色，数字更大，字距紧。
4. **副标题** —— 墨色衬线，含 `·` 分隔与里程。
5. **粗分隔线** —— 砖红 `#96442e`，**5px**（刻意粗，不是发丝线）。
6. **印章** —— 圆形砖红描边 + 纸色底；三行砖红字（状态 / `✓ 核验方式` / 日期）；
   中间一条短横线；**整体旋转约 −10°**。对应本 skill 的 `verify[]`。
7. **路线图** —— 见 §6。
8. **文案块** —— 居中两行，句中的关键数字用橙色（如「一条 **60** 年的铜矿公路」）。
9. **数据条** —— 墨色细框 + 两条灰橄榄竖分隔线（1/3、2/3，上下内缩）；
   每格 = 超大字重数字 + 小号单位（基线对齐数字底部）+ 一行说明。
   **只有中间一格数字用橙色**，左右两格用墨色。
10. **胶囊标签行** —— 4 个圆角胶囊，砖红描边 + 砖红字 + `#` 前缀，底色 `#ede7cf`。

## 6. 路线图配方（本语言最有价值的部分）

原图的路线**不是普通折线**，是**地图公路符号**。逐层：

| 层 | 做法 |
|---|---|
| ① 底 | 纸色 + **极淡等高线**：`#e8e2d2`（只比纸底暗 3%），1px，不规则闭合曲线，散布 3–4 组 |
| ② 主路线 | **实心粗橙描边**（`#d9561e`，约 12px @1080 ≈ 1.1% 宽）+ **沿中心线的纸色短划线**（公路符号惯例） |
| ③ 边缘质感 | 描边**不是直线折角**——边缘带轻微手绘抖动（每段有 1–3px 的起伏） |
| ④ 节点 | **空心圆环**：纸色填充 + 橙色描边（≈3px），压在线中央 |
| ⑤ 标签 | 地名（**墨色衬线**）+ 里程（**橙色，同基线，地名在前**），如「草铺 38km」 |
| ⑥ 引线 | 标签到节点之间用**细虚线**（灰橄榄/墨，1px，斜向） |
| ⑦ POI 图标 | 加油站 / 汽车等，**砖红或绯红**，离线偏移放置（不压线） |
| ⑧ 装饰符号 | 小房子（村落，三色）、山形三角（灰橄榄，成对） |

**实测节点序列**：昆明 0km → 碧鸡关 22km → 草铺 38km → 禄脿 55km → 易门 103km → 小绿汁观景台 134km。
起讫点用**实心圆点**，中途点用**空心圆环**。

**与现有 `build_viz.py` 路线图的差别**：现有是「累计里程折线 + 节点方块」，
表达**里程进度**；本配方表达**地理形状**（有弯曲、有方位），不表达累计值。
**两者不是升级关系，是两个不同的图**——不要用本配方替换现有的。

## 7. 测量方法与原始读数

方法：本机 `screenshot-forensics` skill 的 `scripts/inspect.py` + 自写的四遍脚本
（色相直方图 / 色相聚类 / 行投影 / 结构线扫描 / 切块放大目视复核）。

**原始读数**：

- 全局主色 `#f0e8d8` 量化桶占 **66.27%**；精确众数 `#f4eede`。
- 墨色众数 `#392b1e`（1642px）／`#3a2c1f`（954px）。
- 强调色相分布：`H≈15°` **26 551px**（众数 `#d9561e`）；`H≈0°` **7 464px**（众数 `#96442e`）。
- 次要色众数 `#bcb99a`（1344px，H=54.7° S=0.18 V=0.74）／`#bdb5a2`（H=42.2° S=0.14 V=0.74）。
- 结构线扫描（>60% 覆盖）：横线 y = 26-27 / 34 / **393-397** / **1166-1167** / **1300-1301** / 1405 / 1412-1413；
  竖线 x = 26-27 / 34 / 1045 / 1052-1053。
- 内容栏边界：非背景像素 x 极值 `26`–`1053`（含框）；排除框列后正文栏为 `72–1007`。

**⚠️ 两处测量陷阱（已在 `screenshot-forensics` 有对应纪律）**：

1. **路线橙被 JPEG 拖灰**。细描边的实测众数是 `#c95a2f`／`#be663e`（每色仅 5px），
   明显偏灰；而大块实底的「80」是干净的 `#d9561e`。按「细笔画 S/V 不可信」纪律，
   **取大块实底为真值**。
2. **「绿」不存在**。色相聚类在 H 80–150° 只找到 **2 个像素**；切图放大后确认那是
   **三座小房子**（`#d9561e` / `#96442e` / `#bdb5a2`）。目视误判为「绿树」——
   单靠肉眼会给这套语言补一个不存在的绿色。

**未核实项（不猜）**：

- 原图所用具体字体（只写可见特征，见 §3）。
- 海报的实际产出工具（推测为设计软件手工排版，非模板）。
- 路线图的地理精度：形状是**示意性**的，未与真实路网比对。

## 8. 接入前必须拍板的三个决策

**决策 1：产物形态 —— 独立渲染器，还是现有渲染器的一个主题开关？**

- **推荐：独立脚本 `scripts/build_poster.py`**，输入同一份 `itinerary.json`，输出**单页 3:4 海报**。
  理由：它是**另一种产物**（分享/封面）而非路书皮肤；塞进 `build_swiss.py` 会让该文件同时承担
  两套互相冲突的令牌（§1 的五行冲突），正是当年「功能版」退役的成因。
- **代价**：`scripts/check_quality.py` 需要加一个 `poster` 模式。现有门禁会因
  「多色」「大圆角」判 fail——**这是门禁按设计语言工作，不是 bug**。
- **不推荐**：在 `build_swiss.py` 里加 `--theme print`。那等于把 §1 的五行冲突塞进同一个文件。

**决策 2：色板冲突要不要开口子？**

现有纪律「单一强调色」已有**一个例外**：`viz.swimlane`（因为「哪个城市」本身是信息，
见 `design-language.md` §3）。本语言会是**第二个例外**，性质相同——
橙/砖红/灰橄榄各自承载不同语义（强调 / 核验与标签 / 结构线）。
**建议**：若接入，在 `design-language.md` §3 的例外条款里**并列写明两条例外**，
并各自限定适用范围，不要让例外变成默认。

**决策 3：印章 ←→ `verify[]` 的映射。**

原图的印章「已骑行 ✓ 亲测 2026.10.1」在语义上**就是**本 skill 泳道图的 `verify[]`
（核验行 / 闭环证据）。若接入，应把印章的数据源定为 `viz.swimlane.verify[]` 或新增顶层
`verified` 字段，**不要**让渲染器从别处猜。**注意**：现有 `verify[]` 的文案形态是
「核验：… / 同行：…」这类句子，直接塞进圆形印章会溢出——需要限长（建议 ≤3 行 × ≤8 字）。

## 9. 一句话

**这是一套「一页海报」的语言：纸底、衬线、大数字、一条手绘公路、一枚核验印章。
它和路书是互补的两个产物，不是同一份东西的两套皮肤。**
