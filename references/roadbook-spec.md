# 路书 JSON 字段规范与交付

> 本文件是**渲染侧**的口径：`itinerary.json` 应覆盖哪些字段，以及构建 / 交付怎么走。
> 字段的**内容**由规划阶段（SKILL.md §1–§4）决定；本文件只管「怎么落成一份能渲染的 JSON」。

## 一、字段来源（规划阶段必须问齐的需求口径）

用 `interaction.ask` 一次性问齐（最多 4 个问题，可多选），不要边做边问。**这一步在规划阶段完成**，渲染只消费结果：

1. **出发地、目的地**（单一/环线/多目的地）、**具体出发日期与总天数**。
2. **出行方式**：自驾（车型、能否接受单日 700km+ 赶路日、几位司机）/ 高铁或飞机+当地租车 / 公共交通 / 骑行 / 徒步。
3. **人数与构成**：成人、老人、小孩；是否有人未上高原、慢性病或行动限制；**是否所有人同进同出**（决定要不要出泳道图）。
4. **旅行目的与偏好**：自然风光/人文古迹/美食/摄影/亲子/休闲；必去清单、**明确不想去的地方**（并澄清是"可过境"还是"完全绕开"，规则见 `references/planning-rules.md` §5）；住宿档次与总预算。

用户给了现成行程表/文档时，先完整读取，再进入渲染，不要让用户重述。

## 二、路书 JSON 字段规范

模板示例：`assets/itinerary.sample.json`（自驾，四图全齐）、`assets/itinerary.flight.sample.json`（出境，含 `route_line`/`stays[]`/`flights[]`/`checklist[]`）。构建：`python3 scripts/build_swiss.py <data.json> [out.html]`。

| 字段 | 说明 |
|---|---|
| `title` / `eyebrow` / `title_lines` / `subtitle` | 网页标题、页眉小字、主标题（数组，逐行）、一句话摘要（含出发日、总里程、节奏） |
| `amap_uri` | 唤起高德 App 的完整链接（本机无高德 MCP 时用 `uri.amap.com/search?...&callnative=1` 兜底） |
| `route_line` | 报头下一行路线摘要，纯文本 `A → 转机 → B 3 晚 → C`；**渲染器不做推导，全部手写** |
| `stays[]` | 报头住宿一览：`name`、`nights`（数字）、`status`（"已订"/"待定"）。渲染成「住宿 A ×3 晚 ｜ B ×1 晚」 |
| `weather[]` | 一格 = 主标签 + 温度行 + 说明。`city`（主标签，缺省回退 `label`）、`label`（副标签，仅当给了 `city` 时渲染）、`day`/`night`（数字）、`temp`（自由文本，覆盖 day/night，非城市格写 `"25°/19°"` 或 `"—"`）、`text`（支持 `<br>`）。**非数值格会被气温图整格跳过**，详见 SKILL.md「天气契约」 |
| `weather_note` | 天气数据查询日期、4 天预报窗口说明、温差穿衣总提示 |
| `stages[]` | 分段（去程/游玩/返程），`name`、`color`（blue/green/orange）、`stops[]` |
| `stops[]` | `date`、`time`（出发/夜宿/到达/游玩）、`name`、`km`（里程或班次）、`weather`/`spots`/`food`/`tickets`/`tips`（均可选，缺省不渲染） |
| `flights[]` | **航班时间线**（出境/长途中转）：`leg`（去程/返程/中段，相同值自动归组）、`date`、`no`（航司航班号）、`from`/`to`（含航站楼）、`dep`/`arr`（跨时区**由你算好后填入**，次日写 `00:05+1`）、`dur`（自由文本 `飞 2h5m`）、`pax`（"两人"/"你"——多人不同机时必给）、`note`。**航空段只进这里，不进 `viz.route[]`** |
| `tickets[]` | `name`、`price`、`book`（预约/区间车说明）；`tickets_total` 人均合计；`budget_note` 价格时效声明 |
| `clothing[]` | `group`（场景+温度）、`items`（分层穿搭与装备） |
| `tips[]` | 注意事项条目（行车、高反、车况、预约、应急） |
| `checklist[]` | **可选**，可勾选的出行清单：`text`（必给，支持 `<br>`）、`group`（分组名，相同值的连续项自动归组，按数组顺序）、`when`（自由文本时点标签，如 `T-7` / `出发当天`）。渲染为原生 checkbox，勾选状态只存本机 `localStorage`（key 含行程标识），不联网。**不给则整节不出现、输出与旧版逐字节一致**。tips 讲「要知道什么」，checklist 列「要做完什么」，同一句不两处写 |
| `poster` | **可选出口**，单页 3:4 路线海报（`scripts/build_poster.py`）。字段见 SKILL.md §7b。路线节点优先复用 `viz.route[]`；可选 `path`（0–1 相对坐标）微调示意图。**不给则海报脚本拒绝渲染；精装版 `build_swiss.py` 输出一字节不变**。同一 `poster{}` 还可喂给 `build_route_md.py` 出配套 Markdown |
| `verified_by` | **核实主体**（可选，海报/路线 MD 共用）：`none`（缺省）/ `user` / `source_author`。**只有 `user` 时**路线 MD 才写 `tested: true`。`poster.stamp` 是海报装饰，**不能**据此写成用户已测 |
| `source` | **来源说明**（可选自由文本）：`source_author` 时必填出处；示例样本也应用它标明「示例 / 非核实」。口径同下方「字段来源标注」——写进 MD frontmatter 与「来源与核实」节，不新增平行体系 |
| `decisions[]` | **论证字段**（渲染时忽略，人必读）：`id`/`conclusion`/`reason`/`rejected_alternative`/`tradeoff` |
| `viz` | 图表数据块：`route[]` / `budget[]` / `elevation[]`（可省略）/ `swimlane`（多人并行）；契约见 SKILL.md「二、数据契约」。海报/路线 MD 复用 `viz.route[]` 时：`km` 为**段距**（脚本累加为累计）；到达站 `note` 会出现在路线 MD 分段表备注（如把「72 拐」挂在易门→绿汁的到达站），脚本不自造备注 |
| `footer` | 数据来源与查询日期；可用 `<br>` 换行。**订单截图 / 邮件的汇总来源也写这里**（见下「字段来源标注」） |

### 字段来源标注（订单截图 / 邮件识别）

从用户给的机票、火车票、酒店确认单（截图或邮件）抽取的字段，**确认后才写入**（流程见 SKILL.md §2「订单截图 / 邮件识别」），并按下表标来源。**不新增 `source` 字段**——复用现有的 `note` / `tips` / `footer`：

| 写入位置 | 来源标在哪 | 写法示例 |
|---|---|---|
| `flights[]` | 该行 `note` | `"订单尾号 4821 · 来源：截图 2026-10-02，已与用户确认"` |
| `stays[]`（无 note 字段） | 对应入住日 stop 的 `tips`，或 `footer` 汇总 | `"中之岛东 10/6 入住 · 10/9 退房 · 订单尾号 0317（邮件 2026-09-28）"` |
| 火车（写进 `stops[].km`） | 同一 stop 的 `tips` | `"G2902 订单尾号 5560（截图 2026-10-02）"` |
| 整份行程 | `footer` 一行汇总 | `"航班 / 住宿据用户提供的订单截图与邮件 2026-10-02 抽取并经确认"` |

- 识别不清或单据上没有的字段，值写「未核实」，**不猜、不按常识补**；确认前不渲染。
- **禁止落盘的敏感信息**：完整订单号 / 票号 / PNR（只留**后四位**）、证件号（身份证、护照）、手机号、付款卡号、他人全名（写「你 / 对象 / 两人」）。路书会被转发、打印、在手机上打开。

内容口径（硬要求）：

- **不编造**：天气、里程、门票价格必须来自工具或可追溯来源；查不到就写"以官方为准"或留空，禁止杜撰具体数字。
- 门票价格标注查询年份/日期与"节假日可能浮动"；区间车、索道、骑马等二次消费单列。
- 美食按当地真实特色与**当季**写（不要把季节限定写反）；每站 3–4 项即可。
- 穿着按**最低夜温 + 场景**给分层建议（速干内层/抓绒/冲锋衣/羽绒），并给防晒、雨具、鞋履。
- 每站贴士覆盖：当日驾驶风险、海拔、预约、停车、体力分配。

## 三、构建与自检

1. 在工作区建语义化任务目录（如 `sichuan-roadtrip/`），JSON 与输出 HTML 放其中。
2. `build_swiss.py` 生成单文件自包含 HTML（文件名语义化，不要用 index.html）。
   可选出口：`build_poster.py` 生成单页 3:4 海报（需 `poster{}`）；`build_route_md.py` 生成配套路线 Markdown；`check_quality.py --poster` / `--route-md` 过门禁。
3. **门禁**：`python3 scripts/check_quality.py <输出.html>` 必须 PASS（emoji 残留 / 越界外链 / 至少一张 SVG / AI-slop / 注入噪声）。路线 MD：`python3 scripts/check_quality.py --route-md <输出.md> <data.json>`（累计单调 / 分段和 / 地名 ⊆ JSON / 节点集一致 / 未核实不得 `tested: true`）。人工复核：朱红唯一强调、`line-height ≥ 1.7`、`max-width ≤ 820px`。

## 四、交付

- 用 `present_files` 交付本地 HTML（可附功能版对照）。**本机无 `lark-cli`，不发布公网链接**。
- amapuri 原始链接只能写在网页按钮里，不能作为交付链接。
- 最终回复 ≤300 字、≤8 行，简述页面模块与数据查询日期；远期天气、价格等不确定项一句话提示。
- 若将来 `lark-cli` 可用，再考虑发布 https 链接 + 二维码（当前省略，相关脚本本机不存在）。
